# DroidSeal 1.1.0 发布说明

**发布一个经得起审查的 Android 版本。**

| 字段 | 值 |
|---|---|
| 发布日期 | 2026-10-19 |
| Tag | `v1.1.0` |
| 代码基线 | `542b6aaa88efa4723fed52878d1793706f8340d2` |
| 许可证 | Apache-2.0 |
| 平台 | Windows x64 / Linux x64 |

DroidSeal 1.1.0 是一个本地优先的 Android 发布安全流水线：静态审计、证据驱动修复、
可选的运行时加固、官方对齐与签名、独立验证，全部在一条工作流中完成。本文只描述
冻结的 1.1.0 版本。

## 重点

- **密钥化加固层**：完整性锚点、环境门控与密钥分片折入逐条目密钥派生；manifest、
  运行环境或分片被改变时派生出错误密钥，而不是输出可绕过的警告（P0-A/B/C；P1
  冗余异构检测）。
- **JNI 动态注册恢复**：`JNI_DYNAMIC_REGISTER` 将 native 注册表字符串与 DEX
  类/方法证据交叉验证，暴露静态符号扫描看不到的 native 面。
- **native 线性数据流**：`NATIVE_DATAFLOW_SUSPECT` 以 JNI 导出函数体
  source→sink 共现作为**线性启发式**报告，设计上 `confidence: low`。
- **可执行的 allowBackup 修复**：审计 finding 可转为 AXML 原位补丁
  （`flipAllowBackupFalse`，resId `0x01010280`，长度保持）。
- **TUI 加固向导**：标识符随机化、测试/学习模式与中间产物处理已接入向导与 i18n。
- **诚实 findings**：加固输出 findings 报告；未实现或降级的能力如实报告，绝不静默
  宣称成防护。

## 1.1.0 包含什么

### 审计

- 391 条源码/配置/加固检测器条目（390 个唯一 code）；38 用例内置基准精确率 **76.9%**、召回 **90.9%**。
- TaintBench：39 个 app / 249 条 GT 流，端点级 **171/249（68.7%）**，流级
  **TP 136**。
- 434 个良性 app：数据流引擎 **FP = 0**（95% CI 上界 0.69%）；辅助配置类提示单列。
- JNI 动态注册恢复与 native 线性数据流，口径与启发式限制见上。

### 加固（opt-in）

- DEX payload 加密（AES-256-GCM，逐条目 HKDF 派生密钥）。
- 随机化引导壳、壳入口类 / 容器 magic / meta 键逐构建随机化。
- 方法 CodeItem 抽取 + 惰性还原。
- 字符串加密 + 调用点改写，MUTF-8 安全密文。
- 密钥化防御：完整性锚点、环境门控、密钥分片、冗余异构检测。

### 发布工程

- 按官方顺序执行 `zipalign → apksigner 签名 → 验证`，失败自动回退，每步独立制品。
- SHA-256、JSON/Markdown 报告、CycloneDX SBOM、发布门禁与证据链
  （`releaseDecision` / remediation）。
- CI 执行 `tsc --noEmit`、测试、npm pack 白名单冒烟，并用独立 NDK job 编译生成的
  native 壳源码。

## 1.1.0 不包含什么

以下能力不属于 1.1.0，不能写成 1.1.0 能力：

- `--keystore-bind`
- `--challenge-url`
- `--loader-self-hash`
- `--restore-mode`
- VMP-lite，或任何全指令集 VMP / 白盒密码

## 证据

以下数字是 1.1.0 的发布声明；每项都绑定测量口径。TaintBench 宽松档不可单独引用。

| 声明 | 1.1.0 测量 | 口径 |
|---|---|---|
| TaintBench 端点级 TP | 171 / 249（68.7%） | GT 类中出现 target API |
| TaintBench 流级 TP | 136 | source 与 sink 两端同时命中 |
| 良性 app 误报 | 数据流引擎 FP = 0 | 434 apps，AndroZoo VT=0 代理；95% CI 上界 0.69% |
| 内置检测器基准 | 精确率 76.9% / 召回 90.9% | 38 用例，模式级，MSTG 映射 |
| 发布门禁测试 | 387 / 387 | 1.1.0 发布门禁；构建期全绿不等于运行时正确 |
| 设备验收 | API 26 x86_64 模拟器 | 安装、首启、二次启动、logcat 失败标记 0、卸载干净 |

模拟器记录是验收记录，不是通用设备声明。对你自己的 APK，真机安装仍是最终
运行时判据。

## 安全

- SEC-010（payload DEX 校验和/签名顺序）、SEC-011（抽取 stub 非零填充）、
  SEC-012（标识符随机化破坏 `string_ids` 顺序）已修复，并由产物基线与回归测试覆盖。
- 加固是 opt-in，只修改你显式提供的 APK。
- 默认审计/发布流程不脱壳、不加壳、不注入 Hook/反调试代码。
- 威胁模型与残余风险：[`docs/threat-model.zh-CN.md`](../threat-model.zh-CN.md)。
- 安全策略与披露：[`SECURITY.zh-CN.md`](../../SECURITY.zh-CN.md)。

## 已知限制

- 加固提高逆向成本，不能让逆向变得不可能；root + 持久物理接触下，技术足够强的
  攻击者最终仍能得手。
- `minSdk < 26` 回落到落盘 `DexClassLoader`，隔离性弱于内存路径。
- 不做动态分析/恶意软件沙箱；这些请用 MobSF/APKiD。
- 不交付全量 VMP、白盒 AES 或全指令集 VM 保护。
- 无合同化支持/SLA；独立安全审计与广泛真机矩阵仍在推进。
- 构建期全绿不等于运行时正确；设备验收是唯一可信层。

## 安装

```bash
npm install --global droidseal
# 或
pip install droidseal
```

确认版本：

```bash
droidseal --version
```

预期：`1.1.0`。

## 从 1.0.1 升级

1. 通过你的渠道安装 `1.1.0`。
2. 重新运行 `droidseal doctor`。
3. 在测试制品上重新跑审计/加固流程。
4. 在发布前用自己的设备矩阵重新测试已签名 APK。

加固仍是 opt-in。不要假设 1.0.1 产出的 APK 具备 1.1.0 的加固行为。

## 发布完整性

官方 1.1.0 制品从 tag `v1.1.0`、commit
`542b6aaa88efa4723fed52878d1793706f8340d2` 构建。GitHub Release 发布
Windows zip、Linux tar.gz 与 `SHA256SUMS`。每个归档内包含 CycloneDX bundle
SBOM（`third-party/bundle-sbom.cdx.json`）。安装前校验归档：

```powershell
Get-FileHash .\droidseal-1.1.0-windows-x64.zip -Algorithm SHA256
```

```bash
sha256sum droidseal-1.1.0-linux-x64.tar.gz
```

npm 启动器每次运行都会校验 bundle 的 SHA-256 与固定构建元数据。校验和只把下载
制品绑定到发布记录，不证明运行时安全。
