# DroidSeal v1.0.1 — Release Notes

> 发布状态：公开稳定版 · 2026-10-17 · commit `0ff5fb3206e8d05d19de7e23e5c3985438efe41a`  
> 适用平台：Windows x64 / Linux x64  
> 安装渠道：GitHub Releases · npm · PyPI

## 摘要

DroidSeal 是一个本地优先的 Android 发布安全流水线，覆盖商业加固前的完整发布路径：环境诊断、源码与 APK 审计、证据驱动的修复、可选运行时加固、官方顺序的 `zipalign → apksigner → verify`，以及最终报告与发布门禁。所有分析、改写与签名编排均在本机执行；默认流程不上传 APK、路径或签名材料。

v1.0.1 是 1.0 线的稳定维护版本，重点是把审计、加固、发布门禁与可复现证据链收敛到同一套 CLI、输出目录和报告格式中。它不是“不可逆加固”或“全指令集 VMP”的声明；运行时行为仍以设备安装/启动验收为准。

## 本版能力

### 审计与证据

- **静态审计**：379 条源码/配置/加固模式检测器（373 条基础检测器 + 6 条配置/加固类检测器），覆盖加密、网络、存储、组件、权限、输入输出、配置、生命周期、隐私合规与并发；每条检测器经正/负精度用例门禁。
- **APK 全维度审计**：签名方案、合规配置、深链、资源密钥、DEX、ELF、NSC、WebView、SSL、31 类凭据与端点提取；输出置信度分级与交叉证据，扫描不完整时失败关闭。
- **污点与行为分析**：19 项污点分析（14 类 source / 15 类 sink、sanitizer 建模、生命周期与回调入口、跨函数/跨组件/库间/隐式流传播、反射解析、SDK 版本化模型）；30 条行为规则（键盘变体、勒索、挖矿、广告欺诈、DEX 加载、命令执行等）与加权恶意评分。
- **供应链与报告**：CycloneDX 1.5 SBOM、30 条离线已知漏洞快照、8 条 OSV 离线快照；支持 HTML、SARIF 2.1.0、PDF、MASTG/MASVS、POC、历史对比、PR 评论与 MobSF JSON 导出。

### 加固与发布

- **可选运行时加固**：18+ 个加固生成器，包括 DEX 加密加载、轻量 VMP 指令化、控制流平坦化、反调试与 ptrace、环境深度检测、多文件完整性、运行时痕迹清理、密钥掩码、死代码注入、原生 SO 混淆、Dex2C、指令级等价变换、主动对抗响应与多算法加密。
- **密钥化加固层**：完整性锚点（P0-A）、环境门控（P0-B）、密钥分片（P0-C）与冗余异构检测（P1）折入 DEX 逐条目密钥派生；可选 `--keystore-bind` 与 `--challenge-url` 将派生输入外置到 Android Keystore 或服务端。相关如实边界见下方“验证与证据”。
- **发布工程化**：置信度感知门禁（`pass / review / block`）、证据包、签名精审、加固覆盖度评分（7 类资产，0–100）、复测闭环（`re-test --fail-on-remaining`）、R8 keep 规则模板与签名轮换清单。
- **动态验证**：adb 桥接的 8 个运行期信号——设备矩阵、定向 logcat、UI 冒烟、崩溃/ANR、多设备遍历；静态与动态证据可交叉升级。
- **本地优先**：默认不脱壳、不加壳、不注入 Hook/反调试代码；APK 加固模式必须显式 opt-in，且只修改用户显式提供的输入 APK。

![Figure 2. 密钥化防御与加固 APK 产物契约](https://raw.githubusercontent.com/noontiger/droidseal/main/docs/figures/fig2-keyed-artifact.png)

**Figure 2. 密钥化防御与加固 APK 产物契约。** a 展示构建期派生输入与干净/篡改两条运行时路径；b 把最终归档条目映射到 H1–H6 构建期门禁。H1–H6 是必要条件而非充分条件：设备安装/启动仍是验收门。

## 验证与证据

v1.0.1 的发布证据按以下层级记录；每层回答不同问题，不能互相替代：

| 层级 | 本版证据 | 能证明什么 |
|---|---|---|
| 单元与回归 | 264 个测试通过、0 失败 | 密码学布局、URL 补丁、容器格式不变量 |
| 安全回归 | SEC-010 / SEC-011 / SEC-012 修复与回归断言 | 具体触发条件已被关闭 |
| 产物基线 | H1–H6：loader 存在且 stored、容器 magic 合法、明文 DEX 无密钥材料、壳 manifest 存在 | 最终 APK 仍满足结构契约 |
| VMP-lite | API 26 x86_64 模拟器：5/5 注册，`vmLeaf(21)=120` 与原版一致；非 `(I)I` 方法保持 stub + 惰性还原 | 已接线叶子子集可执行 |
| 设备验收 | API 26 x86_64 模拟器：安装、首启、二次启动、logcat 失败标记、卸载 | 运行时启动与解密链可用 |

![Figure 3. 发布声明的证据阶梯](https://raw.githubusercontent.com/noontiger/droidseal/main/docs/figures/fig3-evidence-ladder.png)

**Figure 3. 证据阶梯。** 每层回答不同问题：单元测试证明实现不变量；对抗回归证明某个修复关闭了特定触发条件；产物基线证明最终 APK 仍满足结构契约；设备验收是唯一能支撑运行时声明的层。该图是示意，不是测量结果。

**如实边界：**构建期全绿不等于运行时正确。v1.0.1 的首轮模拟器验收曾在 264/264 测试与 H1–H6 全绿时首启崩溃，随后定位并修复三个构建级缺陷：校验和/签名顺序颠倒（SEC-010）、方法抽取 stub 残留非零节区填充（SEC-011）、标识符随机化破坏 `string_ids` 字典序（SEC-012）。三修齐备后复测安装、首启、二次启动、logcat 与卸载全部通过。该类缺陷只有设备层能抓住，因此设备安装/启动仍是唯一可信验收。

本版交付 VMP-lite 子集，不包含完整 VMP、白盒 AES 或全指令集 VM 保护；加固提高逆向成本，但不使逆向不可能。root + Frida 环境下的内存 DEX dump 不能被任何离线加壳方案完全阻止。具体残余风险与攻击面见[威胁模型](../threat-model.md)与[安全台账](../security-ledger.md)。

## 安装

```bash
# npm
npm install --global droidseal

# PyPI
pip install droidseal
```

Windows：解压 `droidseal-1.0.1-windows-x64.zip` 后双击 `droidseal-gui.cmd`，或在 PowerShell 中运行 `droidseal.exe`。  
Linux：解压 `droidseal-1.0.1-linux-x64.tar.gz` 后运行 `./droidseal`。  
源码构建（Bun 1.3+）：

```bash
git clone https://github.com/noontiger/droidseal
cd droidseal
bun install --frozen-lockfile
bun run dev
```

> Windows 双击 exe 被 SmartScreen 拦截时，右键 → 属性 → 解除锁定。TUI 需在终端中运行。

## 兼容性与已知边界

- **平台**：Windows x64 / Linux x64；TUI 需要支持 ANSI/Unicode 的交互式等宽终端。
- **运行时依赖**：npm 包需要 Node.js ≥ 18；JDK、Gradle 与 Android Build Tools 按流程自动发现或下载；源码运行需要 Bun 1.3+。
- **加固模式**：显式 opt-in；仅修改用户提供的 release APK；不替代商业加固、动态沙箱或恶意软件分析。
- **能力边界**：不含完整 VMP / 白盒 AES；加固不保证抵抗持续物理接触与内存 dump；设备安装/启动验收是唯一运行时证据。
- **发布纪律**：本地验证与本地 tag 是自动步骤，上传与发布始终是人工显式操作。
