# DroidSeal 1.1.0

**Ship an Android release you can defend.**

| Field | Value |
|---|---|
| Release date | 2026-10-19 |
| Tag | `v1.1.0` |
| Base commit | `542b6aaa88efa4723fed52878d1793706f8340d2` |
| License | Apache-2.0 |
| Platforms | Windows x64 / Linux x64 |

DroidSeal 1.1.0 is a local-first Android release security pipeline: static audit,
evidence-driven remediation, optional runtime hardening, official alignment and
signing, and independent verification in one workflow. This note describes the
frozen 1.1.0 release only.

## Highlights

- **Keyed hardening layers** — the integrity anchor, environment gate and key
  sharding are folded into per-entry key derivation, so a changed manifest,
  changed environment or changed shard derives the wrong key instead of
  emitting a bypassable warning (P0-A/B/C; P1 heterogeneous detection).
- **JNI dynamic-register recovery** — `JNI_DYNAMIC_REGISTER` correlates native
  registry strings with DEX class/method evidence, exposing a native surface
  that a static symbol scan cannot see.
- **Native linear dataflow** — `NATIVE_DATAFLOW_SUSPECT` reports JNI
  exported-function source→sink co-occurrence as a **linear heuristic**, with
  `confidence: low` by design.
- **Actionable `allowBackup` remediation** — an audit finding can be turned
  into an in-place AXML patch (`flipAllowBackupFalse`, resId `0x01010280`,
  length-preserving).
- **TUI hardening wizard** — identifier randomization, test/learning modes and
  intermediate-artifact handling are wired through the wizard and i18n.
- **Honest findings** — hardening emits a findings report; unimplemented or
  degraded behavior is reported as a finding, never silently claimed as
  protection.

## What is in 1.1.0

### Audit

- 391 source/config/hardening detector entries (390 unique codes), measured at **76.9% precision /
  90.9% recall** on the 38-case built-in bench.
- TaintBench: **171/249 endpoint TP (68.7%)**, **136 flow TP** on 39 apps /
  249 ground-truth flows.
- 434 benign apps: **dataflow-engine FP = 0** (95% CI upper 0.69%); auxiliary
  config hints are reported separately.
- JNI dynamic-register recovery and native linear dataflow, with the
  confidence and heuristic limits stated above.

### Hardening (opt-in)

- DEX payload encryption (AES-256-GCM, per-entry HKDF-derived keys).
- Randomized bootstrap shell, shell entry-class / container-magic / meta-key
  randomization per build.
- Method code-item extraction with lazy restoration.
- String encryption with call-site rewrite and MUTF-8-safe ciphertext.
- Keyed defenses: integrity anchor, environment gate, key sharding, and
  redundant heterogeneous detection.

### Release engineering

- `zipalign → apksigner sign → verify` in the official order, with automatic
  rollback and an independent artifact per step.
- SHA-256 digests, JSON/Markdown reports, CycloneDX SBOM, a release gate, and
  an evidence chain (`releaseDecision` / remediation).
- CI runs `tsc --noEmit`, the test suite, an npm-pack whitelist smoke, and a
  separate NDK job that compiles the generated native shell sources.

## Not in 1.1.0

The following are not part of 1.1.0 and must not be presented as 1.1.0
capabilities:

- `--keystore-bind`
- `--challenge-url`
- `--loader-self-hash`
- `--restore-mode`
- VMP-lite or any full-instruction-set VMP / white-box crypto

## Evidence

The numbers below are the 1.1.0 release claims. Each is tied to its measurement
criteria; do not quote the lenient TaintBench tier alone.

| Claim | 1.1.0 measurement | Criteria |
|---|---|---|
| TaintBench endpoint TP | 171 / 249 (68.7%) | target API present in the GT class |
| TaintBench flow TP | 136 | both source and sink ends hit |
| Benign-app false positives | dataflow-engine FP = 0 | 434 apps, AndroZoo VT=0 proxy; 95% CI upper 0.69% |
| Built-in detector bench | precision 76.9% / recall 90.9% | 38 cases, pattern-level, MSTG-mapped |
| Release gate tests | 387 / 387 | 1.1.0 release gate; build-time green is not runtime proof |
| Device acceptance | API 26 x86_64 emulator | install, first launch, second launch, zero logcat failure markers, clean uninstall |

The emulator record is an acceptance record, not a universal device claim.
Real-device install remains the authoritative runtime check for your own APK.

## Security

- SEC-010 (payload DEX checksum/signature ordering), SEC-011 (non-zero
  extraction-stub padding) and SEC-012 (identifier randomization breaking
  `string_ids` ordering) are fixed and covered by the artifact baseline and
  regression tests.
- Hardening is opt-in and modifies only the APK you explicitly supply.
- Default audit/release flows do not unpack, pack, or inject hooks/anti-debug
  code.
- Threat model and residual risks: [`docs/threat-model.md`](../threat-model.md).
- Security policy and disclosure: [`SECURITY.md`](../../SECURITY.md).

## Known limitations

- Hardening raises reverse-engineering cost; it does not make reverse
  engineering impossible. On rooted devices with sustained physical access, a
  sufficiently skilled attacker can eventually win.
- `minSdk < 26` falls back to a file-backed `DexClassLoader`; isolation is
  weaker than the in-memory path.
- No dynamic analysis or malware sandbox; use MobSF/APKiD for that.
- No full VMP, white-box AES, or full-instruction-set VM protection.
- No contractual support/SLA. Independent security review and a broad
  physical-device matrix are still ahead of the project.
- Build-time green does not prove runtime correctness; device acceptance is
  the only trustworthy layer.

## Install

```bash
npm install --global droidseal
# or
pip install droidseal
```

Verify the installed version:

```bash
droidseal --version
```

Expected: `1.1.0`.

## Upgrade from 1.0.1

1. Install `1.1.0` from your channel of choice.
2. Re-run `droidseal doctor`.
3. Re-run your audit/hardening flow on a test artifact.
4. Re-test the signed APK on your own device matrix before shipping.

Hardening remains opt-in. Do not assume that an artifact produced by 1.0.1 has
the 1.1.0 hardening behavior.

## Release integrity

Official 1.1.0 artifacts are built from tag `v1.1.0` at commit
`542b6aaa88efa4723fed52878d1793706f8340d2`. The GitHub Release publishes the
Windows zip, Linux tar.gz, and `SHA256SUMS`. Each archive includes a CycloneDX
bundle SBOM at `third-party/bundle-sbom.cdx.json`. Verify the archive before
installing:

```powershell
Get-FileHash .\droidseal-1.1.0-windows-x64.zip -Algorithm SHA256
```

```bash
sha256sum droidseal-1.1.0-linux-x64.tar.gz
```

The npm launcher verifies the bundle SHA-256 against pinned build metadata on
every run. Checksums bind a downloaded artifact to a published record; they do
not establish runtime safety.
