# DEX 方法/类级混淆——受控子集接入设计（长期路线 ①）

> 状态：设计就绪，待真机设备矩阵验证后接入主线。本设计遵守项目边界：改写只对
> 白名单方法/类生效（失败关闭），不对未知 APK 事后合成；运行时行为在真机矩阵
> （启动链路、反射/注解、动态加载、JNI 注册、Kotlin 内联等场景）验证前不启用。

## 目标

在既有字符串安全（`dex-string-crypto` + 字符串加密桩）基础上，对**白名单内的
方法/类名**做确定性短名重命名（如 `computeToken` → `a`），降低静态逆向阅读
门槛。只改名称，不改调用语义（方法 ID 由 DEX 内部索引引用，重命名不破坏调用
图；类名重命名需同步修改字符串常量里的类描述符，超出本子集）。

## 范围与边界（失败关闭）

| 项 | 决策 |
|---|---|
| 白名单 | 仅显式列出的方法/类名（`keep` 之外的才可重命名）；未列入的一律保留 |
| 只读校验 | 任何一项预检失败（解析失败、ID 越界、字符串引用冲突）即整体失败，不写出 |
| 类名 | 本子集**不重命名类名**（类描述符散落于字符串池/反射，需全链路验证） |
| 方法名 | 仅重命名**非 override、非 native、非注解、非 JNI 注册**的方法 |
| 调用语义 | 重命名后调用图不变（方法引用按 ID），但反射/`getDeclaredMethod` 等按名字查找的会失效——白名单必须排除 |
| 设备矩阵 | 接入主线前需在真实设备验证：启动、Activity 生命周期、广播/服务、动态加载、Kotlin 内联、R8 混淆叠加 |

## 白名单映射工具

`scripts/generate-method-obfuscation-plan.ts`（随本设计一起提供）：

- 输入：`--method <类名#方法名>` 列表（白名单中允许重命名的方法）；
- 输出：确定性短名映射（`computeToken` → `a`）+ `INTEGRATION.md` 接入指南
  （含必须排除的类别：override/native/JNI 注册/反射查找/注解处理）；
- 失败关闭：重复短名、冲突、空列表即报错，不产出部分映射。

## 接入主线的验证矩阵（设备测试，发布前执行）

1. 冷启动 + 主 Activity 生命周期（含旋转/多窗口）；
2. Service/BroadcastReceiver/AIDL 绑定；
3. 反射/注解处理（如 Room/Retrofit/协程）全链路；
4. 动态加载（`DexClassLoader`）与插件化；
5. JNI `RegisterNatives` 注册的方法不重命名（白名单排除）；
6. 与 R8/ProGuard 混淆叠加后的稳定性；
7. `adb shell` 下无崩溃/ANR/ClassNotFoundException。

## 与现有能力的关系

- 字符串安全（加密桩）：已接入源码侧工具链 ✓；
- 方法混淆（本设计）：待设备矩阵验证后接入；未验证前保持研究级（`dex-writer`
  原语可用但不出现在 14 步流水线中）。
