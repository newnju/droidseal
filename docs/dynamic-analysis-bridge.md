# 动态分析外部衔接指南（长期①——MobSF 缺口的边界兼容方案）

> DroidSeal 定位**本地优先、纯静态**（不内置模拟器/运行时/联网动态分析）。
> 动态验证能力通过**外部工具衔接**获得：静态审计发现 → 外部动态验证 → 回填结论。
> 本指南说明衔接方式，不改变本地优先边界。

## 为什么不做内置动态分析

- 动态分析需要模拟器/真机 + 运行时插桩 + 网络代理——与本地优先、不联网边界冲突；
- 动态环境差异大（Android 版本/架构/ROM），内置维护成本高、误报风险大；
- 静态审计已覆盖绝大多数发布前风险；动态验证按需进行更高效。

## 衔接工作流

```text
DroidSeal 静态审计（报告：发现 + 门禁 + 修复包）
   → 选定需动态验证的发现（反编译核验建议节已列出候选）
   → 外部工具动态验证（下表按发现类型给建议）
   → 人工回填结论（确认/排除/升级处置）
```

## 按发现类型的动态验证建议

| 发现类型 | 外部验证工具 | 验证点 |
|---|---|---|
| 组件暴露（EXPORTED_*） | **drozer** | `run app.activity.info -a <pkg>` 确认可被外部启动；`adb shell am start` 实际拉起 |
| 深链/Intent | **drozer / adb** | `am start -a android.intent.action.VIEW -d <deeplink>` 验证可达性与参数注入 |
| WebView 漏洞 | **Frida / 模拟器** | 注入脚本枚举 `addJavascriptInterface` 接口、验证 `setAllowFileAccess` 等运行时状态 |
| 敏感数据流（SOURCE_DATAFLOW） | **Frida / 网络代理** | Hook 源方法追踪数据实际流向；代理抓包确认明文传输 |
| 弱加密 | **Frida** | Hook `Cipher.getInstance` 观察实际算法/模式/IV |
| 硬编码密钥 | **Frida / 静态复核** | 用密钥解密样本验证可用性（确认才算有效） |
| 供应链组件 | **运行时库加载检查** | `adb shell dumpsys package` / Frida 枚举加载的 .so |

## 工具建议

- **Frida / Objection**：动态插桩（Hook 方法、枚举类、追踪调用）；
- **drozer**：Android 攻击面探索（组件/Intent/内容提供器）；
- **模拟器 + 网络代理**（mitmproxy/Charles）：流量记录与改包；
- **MobSF 动态模块**（若已部署）：可直接复用其模拟器动态分析。

## 边界

- 衔接是**人工工作流**（非自动化集成）——DroidSeal 报告提供候选清单与验证建议；
- 动态验证结论由人工回填到发布决策（不自动改变门禁）；
- 所有动态操作在**本地设备/模拟器**进行，不引入云服务依赖。
